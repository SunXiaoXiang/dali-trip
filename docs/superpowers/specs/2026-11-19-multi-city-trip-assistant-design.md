# 多城市旅行助手 设计文档

日期：2026-11-19
状态：已确认方向，待评审文档

## 1. 背景与目标

现状：仓库是一个只服务「大理 5天4晚」的旅行助手（地图首页 + 行程任务 + 小红书/抖音风格攻略 + 应急页），
所有内容写死在 `data.js`、`trip.js` 中，换城市需要重写代码。

目标：每次出门前，跟 AI 助手聊几分钟，就能得到一个可以发到群里的城市旅行助手；同一个网站管理所有旅行。

使用者：
- **策划者**（仓库主人）：决定去哪、玩什么，通过聊天让 AI 生成、修改攻略。
- **团员**：只读使用，打开链接、勾选任务、看地图和应急信息。

已确认的范围决定：
- 一趟旅行 = 一个城市。
- 内容来源第一版 = 与 AI 助手聊天生成数据文件。
- 同一个网站，首页为「我的旅行」列表，每趟有独立链接。
- 每个城市都有攻略笔记，由 AI 与行程一起生成。
- 整体做法：一套程序 + 每趟一份 JSON 数据文件（纯静态，GitHub Pages 部署）。

本版不做：页面编辑器、从小红书/抖音导入、高德收藏导入、团员间同步勾选、一趟多城市。
数据结构需不阻碍以后加入这些能力。

## 2. 用户流程

1. **策划**：策划者提供城市、天数、出发日期、人数、偏好与禁忌、预算、已订住处（若有）。
   AI 至多追问 1–3 个问题，生成旅行文件（地点、每日任务、4–8 篇笔记、当地应急信息），
   通过检查脚本后本地预览；策划者提修改意见，AI 修改并重新检查；确认后提交上线并给出链接。
2. **分享**：首页「我的旅行」列表；每趟链接形如 `https://sunxiaoxiang.github.io/dali-trip/#dali-2026-11`，
   团员可「添加到主屏幕」。
3. **旅途中**：按出发日期自动定位到「今天是第几天」，直接显示当天路线和任务；离线时任务和应急信息可用。
4. **结束后**：首页标记「已结束」，仍可查看；本机勾选、收藏、备注保留。

## 3. 数据结构

### 3.1 程序内置（所有城市通用）

从现在的 `trip.js` 移入程序本体：
- `KINDS`：地点图层（景点 sight、美食 food、打卡点 checkin、拍摄点 photo、住宿 stay、交通枢纽 transport、
  滴滴上车点 didi、电梯/无障碍 access）。
- `ALWAYS_ON`：不随「按天筛选」隐藏的图层（didi、access、transport）。
- `NEARBY`：周边设施类型与高德 POI 分类编码（公交、地铁、医院、药店、派出所、公厕、停车场）。
- `EMERGENCY_CALLS`：全国通用电话（110、120、119、122、12301、12345）。

### 3.2 旅行清单 `trips/index.json`

```json
[
  { "id": "dali-2026-11", "title": "大理 5天4晚", "city": "大理", "startDate": "2026-12-05", "days": 5, "emoji": "🏔️" }
]
```

`days` 为游玩天数（不含「出发前」）。首页据此与 `startDate` 计算状态，不需要加载每个旅行文件。

### 3.3 旅行文件 `trips/<id>.json`

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | 与文件名、清单一致，格式 `<城市拼音>-<yyyy-mm>` |
| `title` / `city` | 是 | 标题、城市名（城市名用于高德搜索限定） |
| `center` | 是 | 地图初始中心 `[lng, lat]`，GCJ-02 |
| `startDate` | 否 | 第 1 天日期 `YYYY-MM-DD`；缺省时不自动定位到今天 |
| `travelers` | 否 | 同行描述，如「2 人」 |
| `days` | 是 | 每天主题，下标 0 固定为「出发前」 |
| `places` | 是 | 地点数组，见下 |
| `tasks` | 是 | 任务数组，见下 |
| `notes` | 是 | 攻略笔记数组，见下（可为空数组，此时隐藏攻略 Tab） |
| `safety` | 是 | `{ tips: string[], calls: {tel,label}[] }`，`calls` 为当地补充电话，与全国电话合并显示 |

**place**：`id`、`name`、`kind`（KINDS 之一）、`emoji`、`lnglat`（GCJ-02）为必填；
`keyword`（高德搜索关键词，缺省用 name）、`desc`、`bestTime`、`tips[]`、`note`（关联笔记 id）、
`verified`（坐标是否人工确认，缺省 false）为可选。

**task**：`id`、`day`（0..days.length-1）、`priority`（must / should / optional）、`title` 为必填；
`time`（`HH:MM`）、`place`（地点 id）为可选。同一天的任务按数组顺序，关联地点去重后连成当天路线。

**note**：`id`、`category`、`title`、`coverText`、`slides[]`（`{bg, emoji, title, lines[]}`）、`content`、`tags[]` 为必填；
`coverSub`、`ratio`（封面高宽比，缺省 1.25）为可选。不再包含点赞数、收藏数、评论数、评论列表、背景音乐等虚构数据。

### 3.4 大理数据迁移

把 `data.js` 的 NOTES 和 `trip.js` 的 TRIP/DAYS/PLACES/TASKS/SAFETY_TIPS 合并为 `trips/dali-2026-11.json`；
笔记删除 likes/stars/comments/commentList/music 字段。`startDate` 待策划者提供，迁移时先不填。

## 4. 程序结构

依旧为纯静态网站、经典 `<script>` 加载、无构建步骤。

### 4.1 页面与路由

- **首页「我的旅行」**（新增）：卡片列表，显示城市、标题、日期、天数、状态（即将出发 / 进行中 / 已结束 / 未定日期），
  进行中优先，其余按日期排序。
- **旅行页**：现有四个 Tab（地图 / 行程 / 攻略 / 应急），左上角增加返回首页按钮。
- **路由**：`location.hash`。`#<id>` 打开对应旅行；空 hash 显示首页；找不到时回首页并 toast 提示。
  监听 `hashchange`，切换旅行时重置地图、任务、笔记状态。

### 4.2 「今天是第几天」

`dayIndex = floor((today - startDate) / 1天) + 1`：
- `< 1`：出发前。地图显示「全部」，行程页滚动到「出发前」。
- `1..N`：旅途中。地图自动选中当天并画路线，任务面板显示当天任务。
- `> N` 或无 `startDate`：显示「全部」。

调试参数 `?today=YYYY-MM-DD` 覆盖今天日期，仅用于测试。

### 4.3 文件拆分

| 文件 | 职责 |
| --- | --- |
| `core.js` | `$`、`esc`、`toast`、格式化工具；按旅行隔离的本地存储 |
| `catalog.js` | 程序内置的 KINDS / NEARBY / EMERGENCY_CALLS 等常量 |
| `trips.js` | 读取 `trips/index.json` 与旅行文件、基本结构校验、计算 dayIndex 与旅行状态 |
| `home.js` | 首页列表 |
| `guide.js` | 攻略笔记（由 `app.js` 改造）：瀑布流、竖屏、详情；去掉虚构计数与评论，改为「收藏」与「我的备注」 |
| `assistant.js` | 地图 / 行程 / 应急，改为读取当前旅行对象而非全局常量 |
| `config.js` | 高德 Key 配置（不变） |

删除：`data.js`、`trip.js`（内容迁入 `trips/` 与 `catalog.js`）。

### 4.4 本地存储

键名 `myTrip:<tripId>`，内容 `{ done, starred, notes, layers }`（任务勾选、笔记收藏、我的备注、图层开关）。
首次加载时把旧键 `myTrip` 中的 `done`、`layers`、`starred` 迁移到 `myTrip:dali-2026-11`；
旧 `myComments`（用户在笔记下发的评论）按笔记合并为「我的备注」文本；旧 `liked`、`cLiked`、`followed` 丢弃。迁移后删除旧键。
高德坐标校准结果缓存于 `myTrip:<tripId>:geo`。

### 4.5 离线

Service Worker 预缓存程序文件与 `trips/index.json`；旅行文件在首次打开时由「网络优先、失败回退缓存」策略自动缓存。
缓存版本号随程序文件变化递增。

### 4.6 异常处理

- 旅行文件加载失败且无缓存：旅行页显示「需要联网打开一次」与返回首页按钮。
- 旅行文件结构错误：控制台输出具体字段，页面显示「数据有误」，不白屏。
- 高德不可用：沿用现有降级（地点列表、直线示意路线、周边搜索提示）。

## 5. 生成与质量保证

### 5.1 生成流程（AI 助手执行）

1. 收集信息：城市、天数、出发日期、人数、偏好与禁忌、预算、住处。
2. 生成 `trips/<id>.json`，并在 `trips/index.json` 追加条目。
3. 运行 `node scripts/check-trip.js trips/<id>.json`，必须通过。
4. 本地预览，根据策划者意见修改，重复第 3 步。
5. 策划者确认后提交并推送，返回旅行链接。

### 5.2 检查脚本 `scripts/check-trip.js`

无第三方依赖，失败时列出全部问题并以非零状态退出。检查项：
- 必填字段存在且类型正确；`id` 与文件名一致且在清单中存在。
- `places`、`tasks`、`notes` 各自 id 唯一。
- `task.place` 与 `place.note` 引用存在。
- `place.kind` ∈ KINDS；`task.priority` ∈ {must, should, optional}；`task.day` 在范围内；`task.time` 符合 `HH:MM`。
- 每个地点坐标与 `center` 的距离 ≤ 100 km。
- 第 1..N 天每天至少一条 must 任务。
- 「出发前」包含一条核实类任务（门票、预约、营业时间）。

### 5.3 内容可信度

AI 生成的营业时间、价格、预约规则可能过时：在地点小贴士中标注「出发前核实」，并由 5.2 的最后一项保证提醒存在。
`verified: false` 的地点在卡片上显示「待核实」。

### 5.4 坐标校准

高德搜索服务可用时，旅行页加载后在后台按 `keyword` 串行调用 PlaceSearch（限定 `city`），
命中则替换坐标与地址，结果缓存于本机；未命中保留原坐标并显示「待核实」。依赖高德 Key 的服务平台/安全密钥问题先解决。

### 5.5 测试

- 每次生成：检查脚本通过。
- 每次发布前浏览器冒烟测试：首页列表与状态、打开旅行、四个 Tab、`?today=` 模拟旅途中某天自动定位、断网打开已访问旅行、旧勾选迁移。

## 6. 后续可扩展方向（不在本版）

- 页面编辑器（直接改 `trips/*.json` 或接入数据库）。
- 从小红书/抖音链接或截图提取地点。
- 高德收藏导入。
- 团员同步勾选（需后端，如 Supabase）。
- 一趟多城市（`trips` 内增加 `legs`）。
